# Junior/Middle
### 1. JVM nima?

`JVM` - Java bytecode'ni bajarish uchun JVM Specification(JVMS) tomonidan belgilangan abstract execution machine/runtime environment. JVM bytecode'ni platformadan mustaqil tarzda execute qilish uchun standartlashtirilgan runtime modelini taqdim etadi. 

JVM'ning bytecode execution modeli `stack-based` hisoblanadi: instruction'lar operandlar bilan asosan har bir method frame ichidagi `Operand Stack` orqali ishlaydi. Har bir method chaqirilganda JVM Stack'da yangi Frame hosil bo'ladi; Frame ichida `Local Variables`,`Operand Stack` va method execution uchun zarur runtile ma'lumotlari mavjud.

`JVM Specification` JVM qanday behavior va execution modeliga ega bo'lishi kerakligini belgilaydi, `HotSpot` esa shu specification'ni implement qilubchi konkret JVM implementation hisoblanadi.

JVM bytecode'ni to'g'ridan-to'g'ri CPU instruction sifatida bajarmaydi. JVM implementation bytecode'ni `Interpreter` orqali execute qilish yoki `JIT` compiler yordamida platformaga mos native machine code'ga compile qilib, CPU'da bajarishi mumkin.

Shu sababli Java bytecode bir xil qolgan holda turli platformalarda mos JVM implementation orqali bajarilishi mumkin.

### 2. `.java` va `.class` o‘rtasidagi farq nima?
`.java` fayl — bu dasturchi yozgan manba kod bo‘lib, inson o‘qiy oladigan sintaksisda yoziladi. JVM uni bevosita bajara olmaydi. Shuning uchun javac kompilyatori .java faylni .class faylga — ya’ni bytecodega aylantiradi.

`.class` fayl — bu JVM kontrakti. Unda qat’iy format mavjud:
 - `Magic number (0xCAFEBABE)` — faylning haqiqiy class fayl ekanini bildiradi.
 - `Constant pool` — stringlar, metod nomlari, fieldlar va literal qiymatlar saqlanadi.
 - `Access flags` — class public/final/abstract ekanini ko‘rsatadi.
 - `Fields`, `Methods`, `Attributes` — kod va metadata.

JVM .class faylni ClassLoader subsystem orqali yuklaydi, Verifier uni tekshiradi, so‘ng Execution Engine (Interpreter yoki JIT Compiler) orqali bajaradi.
Bajarilish jarayonida kod Runtime Data Areas (Heap, Stack, Metaspace) bilan bog‘lanadi va oxir-oqibat CPU mashina kodiga aylantiriladi.

------------------------------------------------------------------------------------------------------------------

### 3. Bytecode nima?
`Bytecode` — bu JVM uchun oraliq instruktsiyalar to‘plami, ya’ni `stack-based` virtual machine uchun yozilgan kod.

- Har bir bytecode instruktsiya `opcode + operand` formatida bo‘ladi.
  Masalan:
  - iload_0 → stack’ga birinchi lokal o‘zgaruvchini yuklaydi.
  - iadd → stack’dagi ikki qiymatni qo‘shadi.
  - invokevirtual → metod chaqiradi.

- Bytecode `constant pool` orqali `string literal`, `class nomlari`, `method imzolari` va `field nomlar`iga murojaat qiladi.
- `.class` faylda bytecode method body sifatida saqlanadi.
- JVM bytecode’ni dastlab `Interpreter` orqali bajaradi, keyin `Profiler + JIT Compiler` yordamida `mashina kod`iga o‘tkazadi.
- Shu mexanizm Java’ni platformadan mustaqil qiladi: .class fayl har qanday JVM’da ishlaydi, lekin oxir-oqibat CPU mashina kodiga aylantiriladi.

------------------------------------------------------------------------------------------------------------------

### 4. `javac` nima qiladi?
`javac` — bu Java kompilyatori. U `.java` fayldagi manba kodni `.class` faylga aylantiradi. Jarayon quyidagicha:
- **Lexical analysis** — kod tokenlarga bo‘linadi.
- **Parsing** — tokenlardan **AST (Abstract Syntax Tree)** hosil qilinadi.
- **Semantic analysis** — tiplar, metod chaqiruvlari, class ierarxiyasi tekshiriladi.
- **Bytecode generation** — **AST**’dan .class fayl tuziladi:
  - **Magic numbe**r (`0xCAFEBABE`)
  - **Constant pool** (stringlar, metod nomlari, fieldlar)
  - **Access flags** (public, final, abstract)
  - **Methods va attributes** (bytecode instruktsiyalar)
- **Output** — `.class` fayl JVM uchun universal bytecode formatida saqlanadi.
- Natijada, `.java` fayl → `.class` fayl → JVM → CPU mashina kodi oqimi hosil bo‘ladi.

### 5. JVM nima qiladi? 
  
`JVM` bytecode - CPU architecturega bog`liq bo'lmagan intermediate instruction set hisoblanadi. CPU esa Java yoki JVM bytecode haqida hech qanday ma'lumotga ega emas; CPU faqat o'zining architectureiga tegishli machine instructionlarni bajaradi. Shu sababli JVM Java bytecode bilan CPU o'rtasida abstraksiya qatlamini hosil qiladi. Bir xil .class bytecode Windows, Linux yoki ARM64 kabi turli  platformalarda ishlashi mumkin, chinki har bir platforma uchun mos JVM implementation mavjud. JVM implementation bytecodeni Interpereter orqali execute qilishi yoki JIT compiler orqali platformaga mos native machine codega compile qilish mumkin.

### 6. Interpreter nima?
**Interpreter** — bu JVM Execution Engine’ning bir qismi bo‘lib, bytecode’ni **instruction-by-instruction** bajaradi.

- `JVM` — `stack-based virtual machine`, shuning uchun Interpreter har bir opcode’ni stack ustidagi qiymatlar bilan ishlatadi.
- Masalan:
  - iload_0 → stack’ga lokal o‘zgaruvchini yuklaydi.
  - iadd → stack’dagi ikki qiymatni qo‘shadi.
   
- Interpreter odatda **switch-case loop** kabi ishlaydi: bytecode opcode’ni o‘qiydi, tegishli handler’ni chaqiradi, keyingi instruktsiyaga o‘tadi.

- Bu jarayon **oddiy va portativ**, lekin sekin — chunki har bir instruktsiya alohida interpretatsiya qilinadi.

- Shuning uchun **HotSpot**’da Interpreter faqat boshlang‘ich bajarish uchun ishlatiladi. Profiling orqali “hot” metodlar aniqlanadi va keyin `JIT Compiler` ularni mashina kodiga aylantiradi.

- Interpreter → Profiling → JIT → Code Cache oqimi Java’ni tez va samarali qiladi.
------------------------------------------------------------------------------------------------------------------

### 7. Stack-based JVM degani nima?

JVM stack-based virtual machine.
- Har bir metod chaqirilganda stack frame hosil bo‘ladi:
  - Local variable array.
  - Operand stack.
- Bytecode instruktsiyalari operand stack ustida ishlaydi (`iload`, `iadd`, `istore`).
- Afzalliklari: platform independent, oddiy implementatsiya.
- Kamchiliklari: register-based mashinalarga qaraganda sekinroq → JIT optimizatsiya zarur.

# Senior

### 8. JVM Stack va Operand Stack farqi nima?

`JVM Stack` — bu har bir thread uchun ajratilgan xotira maydoni. Har bir metod chaqirilganda stack frame hosil bo‘ladi. Stack frame ichida:
 - **Local variable array** — metod parametr va o‘zgaruvchilar.
 - **Operand stack** — bytecode instruktsiyalari ishlaydigan joy.
 - **Frame data** — return address va boshqa metadata.

`Operand Stack` — bu stack frame ichidagi operatsion maydon. Bytecode instruktsiyalari operand stack ustida ishlaydi:
 - `iload_1` → operand stack’ga qiymat push qiladi.
 - `iadd` → operand stack’dan ikki qiymatni pop qilib, natijani push qiladi.
 - `istore_2` → operand stack’dan qiymatni pop qilib, local variable array’ga yozadi.

**Xulosa:**
- JVM Stack — **thread-level container**.
- Operand Stack — **frame-level execution area**.
- JVM stack ichida operand stack mavjud, va u bytecode’ni bajarish uchun asosiy mexanizm hisoblanadi.

------------------------------------------------------------------------------------------------------------------

### 9. Stack Frame nima?

**Stack Frame** — bu JVM Stack ichida metod chaqirilganda hosil bo‘ladigan **execution konteyner**.

1. Metod chaqirilganda yangi stack frame yaratiladi.
2. **Local variable array** — metod parametrlarini va lokal o‘zgaruvchilarni saqlaydi.
3. **Operand stack** — bytecode instruktsiyalari shu yerda ishlaydi (iload, iadd, istore).
4. **Dynamic linking** — constant pool’dagi metod va fieldlarga murojaat qilish uchun pointerlar.
5. **Return address** — metod tugaganda qayerga qaytishni ko‘rsatadi.
6. **Exception handling data** — agar metodda xatolik yuz bersa, tegishli handler’ga yo‘naltiradi.

Metod tugaganda stack frame yo‘q qilinadi, va JVM Stack’dan chiqariladi.

### 10. Method chaqirilganda JVM'da nima sodir bo‘ladi?

1. Class Loading & Linking
 - Agar metod joylashgan klass hali yuklanmagan bo‘lsa, ClassLoader subsystem uni yuklaydi.

 - Linking bosqichida constant pool’dagi barcha external reference’lar (metod, field, class nomlari) tekshiriladi va bog‘lanadi.

 - Bytecode Verifier metodning bytecode’ini xavfsizlik qoidalariga mosligini tekshiradi (stack overflow, illegal access, type safety).

2. Stack Frame yaratish
 - Metod chaqirilganda JVM Stack’da yangi stack frame hosil bo‘ladi. Stack frame tarkibi:

 - Local Variable Array → metod parametr va lokal o‘zgaruvchilar.

 - Operand Stack → bytecode instruktsiyalari ishlaydigan joy (push/pop).

 - Dynamic Linking info → constant pool’dagi metod va field reference’lari.

 - Return address & metadata → metod tugaganda qayerga qaytishni ko‘rsatadi.

3. Bytecode Execution (Execution Engine)
 - Interpreter → bytecode’ni instruction-by-instruction bajaradi.

 - JIT Compiler → “hot” metodlarni profiling asosida mashina kodiga kompilyatsiya qiladi.

 - Code Cache → JIT kompilyatsiya qilingan kodni saqlaydi va qayta ishlatadi.

 - Operand stack ustida amallar bajariladi:

 - iload → qiymatni stack’ga push qiladi.

 - iadd → stack’dan ikki qiymatni pop qilib, natijani push qiladi.

 - istore → stack’dan qiymatni pop qilib, local variable array’ga yozadi.

4. Runtime Data Areas bilan ishlash
 - Heap → obyektlar va reference’lar saqlanadi.

 - Metaspace → klass metadata (field, method imzolari).

 - Thread Stack → har bir metod chaqiruviga stack frame qo‘shiladi.

 - PC Register → bajarilayotgan instruktsiya ko‘rsatkichini saqlaydi.

5. Method tugashi
 - Agar metod qiymat qaytarsa → operand stack’dan natija olinadi.

 - Stack frame JVM Stack’dan chiqariladi.

 - Control calling metodga qaytadi.

 - Agar exception yuz bersa → stack frame exception handler’ga yo‘naltiriladi.
